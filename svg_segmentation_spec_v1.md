# Спецификация v1: текстовый запрос → выбор узлов SVG → отфильтрованный SVG

Документ фиксирует **принятые решения** для первой реализации. Код генерировать только по явной просьбе; до этого документ — источник правды для обсуждения и последующей реализации.

---

## 1. Цель v1

- **Вход:** файл SVG `S`, текстовый запрос `q` (например, описание объекта на растре).
- **Выход:** один SVG-файл — **по сути отфильтрованный исходный документ**: остаются **только выбранные** узлы (и минимально необходимая структура для их валидности), **остальное удалено**.
- **Смысл операции:** «оставить выбранное, убрать всё остальное» (изоляция содержимого по запросу, не «вырезать объект из сцены, оставив фон»).

---

## 1.1 Структура SVG и пример «что происходит»

Имелось в виду следующее: обычно на входе **один XML-файл** с **одним корневым `<svg>...</svg>`** (холст), внутри — дерево: `<defs>`, `<g>`, примитивы и т.д. Реже бывают вложенные `<svg>` или нестандартная разметка; для v1 достаточно правила: **основной холст = корневой `<svg>` документа** (если появятся файлы с несколькими корнями — поведение уточняется при первой встрече в коде).

**Пример (схема).** Вход `scene.svg`:

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 100 100">
  <defs>
    <linearGradient id="g">
      <stop offset="0" stop-color="red"/>
      <stop offset="1" stop-color="blue"/>
    </linearGradient>
  </defs>
  <g transform="translate(10,0)">
    <path id="tail" d="M0,0..." fill="url(#g)"/>
    <path id="body" d="M20,20..." fill="green"/>
  </g>
  <rect x="80" y="80" width="10" height="10"/>
</svg>
```

После парсинга на **каждый** узел вешается **`data-local-id`** (см. §1.2). Допустим, по маске и порогу прошли только кандидаты `tail` и `body`.

**Выход:** не выбранные элементы отрисовки удалены; **каждый выбранный лист сохраняется вместе со всей цепочкой предков** до корня `<svg>` (иначе теряются `transform`, клип и т.д. с предков). **Пустые `<g>` не удаляем** — если после выкидывания сиблингов группа стала содержать только выбранное, пусть остаётся как есть. **`<defs>` копируем целиком.**

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 100 100">
  <defs>
    <linearGradient id="g">...</linearGradient>
  </defs>
  <g transform="translate(10,0)" data-local-id="…">
    <path id="tail" d="M0,0..." fill="url(#g)" data-local-id="…"/>
    <path id="body" d="M20,20..." fill="green" data-local-id="…"/>
  </g>
</svg>
```

Расширенная пометка «все связанные теги» (не только предки) **отложена**; в v1 явно: **предки выбранных листьев обязаны остаться в выходе.**

---

## 1.2 Служебная разметка: `data-local-id`

- На **каждый** узел при обходе/нормализации дерева вешается **уникальный** атрибут **`data-local-id`** (строка, стабильная в рамках одного прогона).
- Авторские атрибуты **`id`** и ссылки **`url(#...)` не переименовываем** без отдельной задачи; служебная трассировка — только через `data-local-id`.

---

## 2. Общая схема пайплайна

1. Распарсить SVG; **каждому узлу** назначить **`data-local-id`** (§1.2).
2. Отрендерить **полную сцену** в растр **в «нативном» разрешении** для дальнейшего сравнения с масками кандидатов (согласованно с `viewBox`/размером холста — деталь реализации: один выбранный DPU или размер из атрибутов `width`/`height`).
3. **Для SAM:** изображение **масштабировать** до размера, удобного модели (входное разрешение/лонг-сайд — параметр), прогнать Grounded SAM, получить маску(и) в **разрешении SAM**.
4. **Таргет-маску** привести к размеру **нативного** полного рендера (обратное масштабирование / ресайз маски с тем же соответствием координат, что и для картинки), затем бинаризовать по правилам §7. Если модель вернёт **несколько** масок — поведение (OR, лучшая по метрике, и т.д.) **не фиксируем до экспериментов** с реальным выходом пайплайна (§14).
5. Построить список **кандидатов** (§4).
6. Для каждого кандидата отрендерить маску `C` в **том же нативном** размере, что и полный рендер (§5–6).
7. Сравнивать `T` и `C` **в одной сетке пикселей** (уже после выравнивания размеров).
8. Вычислить **score** (§8), отобрать кандидатов с `score ≥ θ` (§8).
9. Собрать выходной SVG: **удалить не выбранные** drawable-ветки; **сохранить все предки** выбранных; **не чистить** пустые `<g>`; **`<defs>` целиком** (§9).
10. Сохранить отладочные артефакты по возможности — по желанию на этапе реализации.

---

## 3. Растровый фронт (семантика → маска)

- Базовый выбор модели: **Grounding DINO + SAM / Grounded SAM 2** (как в исходном плане); детали тензора/маски **не фиксируем** до экспериментов.
- **Разрешение:** изображение для модели **масштабируется** под ожидаемый вход SAM; полученная маска **масштабируется обратно** к размеру нативного полного рендера, после чего строится итоговая `T` для сравнения с `C`.

---

## 4. Кандидаты

- Кандидаты — **элементы с собственной геометрией** (листья отрисовки), не только `<path>`: `path`, `rect`, `circle`, `ellipse`, `line`, `polyline`, `polygon` и аналогичные векторные примитивы без вложенной геометрии.
- **`<text>` в v1 не кандидаты** (исключаем).
- **`<use>` в v1 не рассматриваем** (нет отдельной ветки разворачивания ссылок).

---

## 5. Рендер кандидата для маски `C`

- Ренерировать **не «поддерево произвольной глубины без контекста»**, а **кандидат в полном контексте всех предков**: в мини-документ (или изолированный рендер) включается **цепочка всех предков** от корня сцены до кандидата, **плюс сам кандидат**.
- **Сиблинги** кандидата в документе **не** включаются (осознанное допущение v1: возможное расхождение с финальной композицией при перекрытиях и полупрозрачности принимается; идеальная пиксельная эквивалентность не цель v1).

---

## 6. Построение маски кандидата из рендера

- Использовать **альфа-канал** результата рендера.
- **Порог по эпсилону не вводим:** пиксель считается принадлежащим маске кандидата, если **альфа ненулевая** (`alpha > 0`). Допускается несовершенная маска (ореол сглаживания и т.п.) — **приемлемо для v1**.
- Белый фон как замена альфе **не требуется**, если рендер даёт корректную альфу.

---

## 7. Таргет-маска `T` и согласование с кандидатами

- Формат выхода Grounded SAM (soft mask, дискретные уровни и т.д.) **не фиксируем** — определяется экспериментами.
- Требование: привести `T` к **бинарной** маске той же размерности, что и рендер, с правилом, **максимально согласованным** с кандидатами: по смыслу «занятый пиксель» для сравнения. Если модель отдаёт альфу — допустимо **ненулевая альфа = занято** (без ε), по аналогии с §6; если отдаётся одноканальная вероятность — зафиксировать в коде один выбранный порог **один раз** после экспериментов и описать в комментарии/README рядом с кодом (не обязательно менять этот документ при каждом твике).

---

## 8. Метрика отбора (score) и порог

- Обозначения: `C` — бинарная маска кандидата, `T` — бинарная маска запроса, пересечение и площади в пикселях.
- **Score (направленное покрытие кандидата таргетом):**

  \[
  \text{score} = \frac{|C \cap T|}{|C|}
  \]

  если \(|C| = 0\) (кандидат ничего не закрасил), кандидат **отбрасывается** (не проходит отбор).

- Смысл: кандидат, **полностью** лежащий внутри таргета, получает **1**, даже если он очень маленький относительно всей маски (в отличие от классического IoU).
- **Порог по умолчанию:** `θ = 0.8` — кандидат попадает в результат, если `score ≥ θ`.
- **Порог обязан быть настраиваемым** (аргумент CLI / конфиг), значение по умолчанию `0.8`.

- **NMS не применяем:** несколько близких по положению кандидатов (глаза, хвост, тело) **могут и должны** пройти отбор, если каждый удовлетворяет порогу.

- **Не объединяем** выбранные элементы в новый искусственный `<g>` ради «сборки»; структура — исходная (предки выбранных узлов сохраняются только настолько, насколько нужно для валидного документа — см. §9).

---

## 9. Выходной SVG и зависимости

- **Один файл** на выходе.
- **Удалено:** не выбранные элементы отрисовки; **сохранены** все **предки** каждого выбранного листа до корня `<svg>` (обязательное правило).
- **Пустые `<g>`:** **не удаляем** намеренно (косметика не важна для v1).
- **`<defs>`:** в v1 **сохраняем целиком**, как в исходном файле (без сборки мусора по неиспользуемым `id`) — проще и надёжнее.
- Ссылки **`url(#id)`** и прочие прямые ссылки на id из атрибутов для v1 покрываются политикой «defs целиком»; отдельный обход графа ссылок для минимизации defs **не обязателен** в v1.
- Расширение «пометить все связанные теги, не только предки» — **не входит в v1**; позже можно добавить явный сбор замыкания по ссылкам поверх полного `defs`.

---

## 10. Зависимости и стили (рамка v1)

- Расширенный разбор CSS, классов, внешних стилей — **вне объёма** текущей фиксации.
- Прямые `url(#id)` в атрибутах учитываются косвенно за счёт **полного `<defs>`**.
- **Внешние ресурсы** (`<image href="https://..."/>`, внешние шрифты, внешние фильтры и т.п.) — **не поддерживаем** в v1; допускается «как получится» при рендере или явный отказ для таких файлов — на усмотрение первой реализации (в спецификации не требуется полнота).

---

## 11. Производительность

- Для v1 **не приоритет**: допускается наивный перебор кандидатов с полноразмерным рендером каждого. Оптимизации (bbox-prefilter, пирамиды) — позже.

---

## 12. Известные ограничения v1 (зафиксировать честно)

- Сравнение маски кандидата (без сиблингов) с маской полной сцены **не гарантирует** совпадение при сложном перекрытии и прозрачности.
- Маски **не обязаны быть идеальными**; ненулевая альфа без ε может давить ореол в метрике — приемлемо.
- Нет `<use>`, нет `<text>` как кандидатов.
- Полный `<defs>` может тянуть лишние ресурсы в файл.
- Внешние ресурсы не в фокусе v1.

## 13. Краткий псевдокод (для будущей реализации)

```
svg = parse(input_path)
assign_data_local_id_every_node(svg)

full_native = render_full(svg, resolution=RENDER_NATIVE)
sam_input = resize_for_sam(full_native, SAM_INPUT_SIZE)
T_sam = query_mask_from_grounded_sam(sam_input, q)  // формат — после экспериментов
T = binarize_query_mask(resize_mask_to_match(T_sam, full_native))

candidates = enumerate_drawable_leaves(svg, exclude={use, text})

selected = []
for c in candidates:
    C = binarize_from_alpha(render_candidate_with_all_ancestors(svg, c, resolution=RENDER_NATIVE))
    if area(C) == 0: continue
    score = area(C & T) / area(C)
    if score >= theta:  // default 0.8, configurable
        selected.append(c)

output_svg = filter_svg_keep_only(
    svg, selected,
    keep_ancestor_chains=True,
    keep_empty_groups=True,
    keep_defs_full=True,
)
save(output_svg)
```

## 14. Открытые пункты (не блокируют документ, уточняются при реализации / экспериментах)

- **Формат выхода Grounded SAM** и **бинаризация** `T` при не-альфа тензорах — после экспериментов; зафиксировать в коде/README рядом с реализацией.
- **Несколько масок** с одного запроса (если появятся): как объединять в одну `T` — **после экспериментов**, в документ можно внести отдельным дополнением.
- Точный выбор **нативного разрешения** рендера (только `width`/`height` из SVG, фиксированный DPU, max side) — параметр реализации; важно лишь **одинаковая сетка** для `full_native` и всех `C`, и согласованный ресайз `T`.
- Файлы с **несколькими корневыми `<svg>`** или без стандартного корня — поведение при первой встрече.

## 16. Опциональные вопросы на потом (не обязательны до кода)

Если при реализации что-то споткнётся — можно отдельно зафиксировать:

1. Точные числа **SAM input size** и политика **aspect ratio** (letterbox vs stretch) при ресайзе картинки и маски.
2. Нужно ли в выходном файле **убирать** `data-local-id` для «чистого» артефакта или оставляем для трассировки.
3. Вложенный `<svg>` внутри корневого: считать отдельным холстом или частью одной сцены.

Пока это можно не решать.
